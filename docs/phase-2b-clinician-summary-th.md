# สรุป Phase 2B สำหรับแพทย์และเจ้าของคลินิก

เอกสารนี้สรุปงาน Phase 2B ในมุมใช้งานจริงของคลินิก ก่อนนำระบบไปทดสอบกับทีมแพทย์และเจ้าหน้าที่

## เป้าหมายของ Phase 2B

Phase 2B เพิ่มความปลอดภัยของการสั่งยาและความพร้อมก่อน pilot โดยเน้น 3 เรื่อง:

- ลดความเสี่ยงจากการสั่งยาที่ชนกับประวัติแพ้ยา
- แจ้งเตือนปฏิกิริยาระหว่างยาตามกฎที่คลินิกดูแลเอง
- ตรวจความพร้อมของระบบก่อนเริ่มใช้กับข้อมูลจริง

## สิ่งที่ระบบทำได้แล้ว

### Drug Catalog

คลินิกสามารถมีรายการยากลางของตัวเองได้ เช่น ชื่อยา รหัส RxNorm ถ้ามี ชื่อสามัญยา ความแรง รูปแบบยา วิธีใช้ และ allergen tags สำหรับช่วยจับคู่กับประวัติแพ้ยา

### Allergy Safety Warning

เมื่อแพทย์หรือเจ้าหน้าที่สั่งยา ระบบสามารถเช็กกับประวัติแพ้ยาที่ active อยู่ของผู้ป่วย แล้วแจ้งเตือนก่อนบันทึกใบสั่งยา

ตัวอย่าง:

- ผู้ป่วยมีประวัติแพ้ penicillin
- แพทย์สั่ง Amoxicillin
- ระบบแสดง warning และบังคับให้ระบุเหตุผลถ้าจะสั่งยาต่อ

### Drug Interaction Warning

คลินิกสามารถกำหนดกฎปฏิกิริยาระหว่างยาได้ เช่น Warfarin + Paracetamol พร้อมระดับความรุนแรง คำอธิบาย และคำแนะนำในการติดตาม

เมื่อสั่งยาใหม่ ระบบจะเทียบกับยาที่ผู้ป่วยใช้อยู่และใบสั่งยาที่ยัง active เพื่อแสดง warning

### Override Reason

ถ้ามี warning แล้วแพทย์ยังต้องการสั่งยาต่อ ระบบจะบังคับให้กรอกเหตุผล เช่น ผู้ป่วยเคยใช้ได้ แพทย์พิจารณาแล้วประโยชน์มากกว่าความเสี่ยง หรือมีแผนติดตามอาการเฉพาะ

เหตุผลนี้ถูกเก็บใน prescription record เพื่อใช้ตรวจสอบย้อนหลัง

### Warning Snapshot

ใบสั่งยาจะเก็บ snapshot ของ warning ณ เวลาสั่งยา ทำให้ตรวจย้อนหลังได้ว่าตอนสั่งยานั้นระบบเตือนอะไร และผู้ใช้งานตอบสนองอย่างไร

### Pilot Readiness Check

เพิ่มคำสั่งตรวจความพร้อมก่อน deploy:

```bash
PRODUCTION_READINESS_STRICT=true npm run production:check
```

คำสั่งนี้ช่วยตรวจค่า config สำคัญ เช่น database, API token, file storage, upload policy และ MIME types

## สิ่งที่ต้องให้แพทย์ช่วยรีวิว

- รายการยากลางควรมี field เพียงพอต่อการใช้งานจริงหรือไม่
- allergy warning จับคู่ถูกต้องพอสำหรับ clinic pilot หรือไม่
- interaction warning ควรเริ่มจากกฎกลุ่มใดก่อน
- severity ของ warning ควรให้คลินิกกำหนดเอง หรือใช้มาตรฐานกลาง
- override reason ที่บังคับกรอกเหมาะสมกับ flow การตรวจจริงหรือไม่
- ข้อความ warning อ่านง่ายและช่วยตัดสินใจได้จริงหรือไม่

## ข้อจำกัดที่ต้องเข้าใจก่อน Pilot

- ระบบยังไม่ใช่ clinical decision support แบบครบถ้วน
- interaction rules ยังเป็นกฎที่คลินิกหรือ admin ตั้งเอง
- ยังไม่มีฐานข้อมูลยาระดับประเทศหรือ commercial drug database
- ระบบช่วยเตือน แต่ไม่แทนการตัดสินใจของแพทย์
- production authentication ขั้นสูง เช่น MFA/identity provider ยังเป็นแผน Phase ถัดไป

## สถานะสำหรับ Pilot

Phase 2B พร้อมเข้าสู่ clinician review และ UAT ได้ โดยควรใช้กับข้อมูลทดสอบก่อน แล้วให้ทีมคลินิกยืนยัน flow ต่อไปนี้:

- ค้นหาผู้ป่วย
- เปิดหน้า Prescriptions
- เลือกยาจาก drug catalog
- กด safety check
- อ่าน warning
- กรอก override reason เมื่อจำเป็น
- บันทึกใบสั่งยา
- ตรวจดู warning snapshot ย้อนหลัง

ผลจาก UAT จะใช้ตัดสินใจว่า Phase ถัดไปควรเน้น production auth, medication knowledge base, หรือ workflow สำหรับ dispensing/pharmacy ก่อน
